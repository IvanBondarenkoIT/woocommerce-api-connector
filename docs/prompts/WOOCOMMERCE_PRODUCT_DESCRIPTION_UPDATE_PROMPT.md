# Промт: Проект обновления описаний товаров WooCommerce из Excel

## Назначение документа

Этот файл — **промт/спецификация для отдельного проекта** (не для текущего репозитория woocommerce-api-connector). Используйте его как ТЗ для реализации инструмента, который:

1. Подключается к WooCommerce по REST API.
2. Читает данные (наименование товара + новое описание) из Excel-файла.
3. Находит товар в WooCommerce по наименованию.
4. Записывает новое описание в товар через API (PUT).

В текущем проекте **только анализ и создание этого промта**; сама реализация делается в **другом проекте**.

---

## 1. Контекст из текущего проекта (woocommerce-api-connector)

### 1.1 Подключение к WooCommerce API

- **Библиотека:** `woocommerce` (Python), версия 3.0.0.
- **Аутентификация:** Consumer Key + Consumer Secret (Basic Auth / query string).
- **Версия API:** обычно `wc/v3` (в .env: `WC_API_VERSION=wc/v3`).
- **Базовый URL:** URL магазина **без завершающего слеша** (например, `https://store.com`).

Переменные окружения (`.env`):

```env
WC_URL=https://your-store.com
WC_CONSUMER_KEY=ck_...
WC_CONSUMER_SECRET=cs_...
WC_API_VERSION=wc/v3
WC_TIMEOUT=30
WC_USER_AGENT=Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (Chrome/120...)
```

- **Обязательно:** для магазинов с Imunify360 (и другой бот-защитой) нужно выставлять **User-Agent** как у браузера; иначе возможен 403. В текущем проекте это делается через `wcapi.session.headers['User-Agent']` или `wcapi._session.headers['User-Agent']`.

Инициализация клиента (псевдокод по текущему проекту):

```python
from woocommerce import API

wcapi = API(
    url=os.getenv('WC_URL'),
    consumer_key=os.getenv('WC_CONSUMER_KEY'),
    consumer_secret=os.getenv('WC_CONSUMER_SECRET'),
    version=os.getenv('WC_API_VERSION', 'wc/v3'),
    timeout=int(os.getenv('WC_TIMEOUT', 30)),
    query_string_auth=True
)
# Установить User-Agent через wcapi.session или wcapi._session
```

### 1.2 Получение товаров (GET)

- **Список товаров:** `GET /wp-json/wc/v3/products`.
- Параметры: `per_page` (макс. 100), `page`.
- Пагинация: пока `len(products) == per_page` — запрашивать следующую страницу; при пустом списке или `len(products) < per_page` — конец.
- В ответе у каждого товара есть поля: `id`, `name`, `description`, `short_description`, `sku`, и др.

### 1.3 Поиск товара по наименованию

- В WooCommerce REST API (wc/v3) есть параметр **`search`** для списка товаров:  
  `GET /products?search=<строка>` — поиск по названию (и не только).
- Для точного сопоставления с Excel: либо получить все товары (с пагинацией) и искать по полю `name` в коде, либо использовать `search` с наименованием из строки Excel и затем проверять точное совпадение/нормализацию (пробелы, регистр, тип кавычек и т.д.).

Важно предусмотреть:

- Несколько товаров в ответе на `search` — выбрать один по политике (точное совпадение, первый, или отчёт о дубликатах).
- Товар не найден — логировать строку из Excel и при необходимости выводить в отчёт.

### 1.4 Обновление описания товара (PUT)

- В **текущем проекте** метода обновления товара (PUT) **нет** — его нужно реализовать в целевом проекте.
- Endpoint: **`PUT /wp-json/wc/v3/products/{id}`**.
- Тело запроса — JSON. Для смены только описания достаточно передать поля:
  - `description` — полное описание (может быть HTML).
  - `short_description` — краткое описание (при необходимости).
- Остальные поля товара при частичном PUT обычно не трогать (либо явно документировать политику: только description/short_description).

Пример тела:

```json
{
  "description": "Новое полное описание товара (можно с HTML)",
  "short_description": "Новое краткое описание"
}
```

- Ключи API должны иметь права **Read/Write** (не только Read).

### 1.5 Ошибки и исключения (по текущему проекту)

Имеет смысл обрабатывать те же типы ошибок, что и в woocommerce-api-connector:

- **401** — неверные ключи (AuthenticationError).
- **403** — часто Imunify360/бот-защита → проверить User-Agent и при необходимости IP whitelist.
- **404** — товар или endpoint не найден (NotFoundError).
- **429** — лимит запросов (RateLimitError); пауза и повтор.
- Таймауты и сетевые ошибки (NetworkError).

Рекомендация: между запросами к API делать небольшую задержку (например, 0.3–1 с), чтобы снизить риск блокировок и 429.

### 1.6 Кодировка и кириллица

- Описания из Excel и для API — в **UTF-8**.
- В Windows при выводе в консоль может понадобиться настройка stdout/stderr на UTF-8 (как в текущем проекте в `connector.py`).

## 2. Работа с Excel

### 2.1 Формат файла

- Формат: **xlsx** (openpyxl в текущем проекте уже используется для Excel).
- Минимальные колонки:
  - **Наименование товара** (название для поиска в WooCommerce).
  - **Описание** (новое полное описание для записи в товар).
- Опционально: колонка для **краткого описания** (`short_description`), колонка **SKU** для альтернативного поиска.

### 2.2 Детали реализации

- Указать: имя листа (или первый лист по умолчанию), номера/имена колонок или строка заголовков.
- Обработка пустых ячеек: пропуск строки или запись пустой строки в API — зафиксировать в ТЗ.
- Обработка дубликатов наименований в Excel: обновлять оба товара или только первый — решить в ТЗ.
- Если в магазине несколько товаров с одинаковым названием — политика: обновлять все, только первый, или выводить предупреждение и не обновлять.

### 2.3 Зависимости

- В целевом проекте достаточно: `openpyxl` для чтения xlsx, `woocommerce`, `python-dotenv`, `requests` (часто уже есть у woocommerce).

## 3. Алгоритм работы (для целевого проекта)

1. Загрузить конфигурацию из `.env` (URL, ключи, версия API, таймаут, User-Agent).
2. Инициализировать WooCommerce API-клиент и установить User-Agent.
3. Открыть Excel-файл, определить лист и колонки (наименование, описание, при необходимости краткое описание).
4. Для каждой строки с данными:
   - Взять наименование из Excel.
   - Найти товар в WooCommerce по наименованию (через `search` и/или перебор полученных товаров с сопоставлением).
   - Если товар не найден — записать в отчёт/лог и перейти к следующей строке.
   - Если найден один (или выбран один по правилам) — выполнить `PUT /products/{id}` с телом `{"description": "...", "short_description": "..."}` (или только нужные поля).
   - Обработать ошибки (повтор при 429, логирование при 4xx/5xx).
   - При необходимости — пауза между запросами.
5. Сформировать отчёт: сколько обновлено, сколько пропущено (не найден товар, ошибка API), список ошибок.

## 4. Нюансы для промта/ТЗ в целевом проекте

Ниже — формулировки, которые можно скопировать в промт или ТЗ для разработки.

### 4.1 Подключение к WooCommerce

- Использовать WooCommerce REST API (wc/v3), аутентификация: Consumer Key и Consumer Secret (query_string_auth=True).
- URL магазина без слеша в конце.
- Обязательно устанавливать User-Agent как у браузера (Chrome), иначе возможна блокировка Imunify360 (403).
- Таймаут запросов задавать из конфига (например, 30 с).

### 4.2 Чтение данных из Excel

- Файл xlsx, минимум две колонки: **наименование товара** и **новое описание**.
- Опционально: краткое описание, SKU. Явно указать, по каким колонкам искать (по имени или индексу) и как обрабатывать заголовок.

### 4.3 Поиск товара по наименованию

- Использовать API: GET products с параметром `search` по наименованию из Excel и/или предзагрузку списка товаров с пагинацией и сопоставление по полю `name`.
- Определить правило сопоставления: точное совпадение строки, нормализация пробелов/регистра, учёт нескольких результатов (один товар / несколько / не найдено).
- Если найдено несколько товаров с одинаковым именем — зафиксировать поведение: обновлять первый, все или не обновлять и писать в отчёт.

### 4.4 Запись нового описания через API

- Использовать **PUT** `wp-json/wc/v3/products/{id}`.
- В теле передавать минимум `description`; при наличии в Excel — и `short_description`.
- Не перезаписывать остальные поля товара (только описание).
- API-ключ должен иметь права Read/Write.

### 4.5 Надёжность и ограничения

- Обрабатывать 401, 403, 404, 429, таймауты и сетевые ошибки.
- Добавить задержку между запросами к API (например, 0.5 с).
- Логировать каждое обновление и каждую ошибку; в конце вывести сводку: обновлено / не найдено / ошибка.

### 4.6 Кодировка

- Везде использовать UTF-8 (файл Excel, запросы/ответы API, логи, консоль при необходимости).
